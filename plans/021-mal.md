## What MAL offers, checked

myanimelist.net and its API host are blocked from the build box, so this
was read from a verbatim mirror of MAL's authorization page, MAL's own
OpenAPI spec (mirrored), and the source of desktop clients that talk to
it today (Taiga, Trackma, MALSync, Mal4J), each cited in the research
notes. What only MAL itself can confirm is marked.

- **Sign-in is OAuth with PKCE, "plain" method only.** A browser opens
  MAL's authorize page, MAL redirects back with a code, the app trades it
  for tokens. S256 is accepted at authorize and then fails at the token
  step (a third party tested it in August 2026).
- **No client secret needed.** An app registered as type "other" gets a
  client ID only; Taiga and Trackma, both desktop clients, work that way.
- **The redirect must be registered exactly.** `http://localhost:PORT/…`
  works (Kometa, Mal4J), so https is not required. A fixed port, since
  wildcards are unconfirmed. A custom URL scheme may work (an Android
  client uses one) but is unconfirmed for type "other".
- **Tokens:** the docs say an hour for access, a month for refresh; real
  answers say 31 days for access. The code reads `expires_in`. Refresh
  tokens rotate but the old one keeps working until it expires (unlike
  Trakt's, which are single-use). Each token is about 1,000 bytes, which
  is tight for one Credential Manager entry (2,560 bytes), so they get one
  each.
- **No scrobbling, no paused position.** A list entry is a status
  (watching, completed, on hold, dropped, plan to watch), an episode
  count, a score and dates. That is all MAL keeps.
- **The API:** read your list (`/users/@me/animelist`, up to 1,000 a
  page, newest change first), update one entry (`PATCH
  /anime/{id}/my_list_status`, form fields `status`,
  `num_watched_episodes`, `score`), remove one, read a title's episode
  count. No CORS, so every call is native, as Trakt's are.
- **No documented rate limit.** Clients keep to about one call a second;
  a ban comes back as an HTML page. The same one-a-second pacing as
  Trakt's writes.
- **Terms (unconfirmed first-hand, page blocked):** don't share the
  client ID with third parties, tell MAL when the app is released, and
  register as Commercial or Non-Commercial. Every open desktop client
  ships its client ID in public source regardless.

## How BlammyTV finds a title on MAL

The app already bridges to MAL ids for AniSkip (`features/stream/
aniskip.ts`) through Fribb's anime-lists dataset: IMDb id plus TVDB
season and episode offset to a MAL entry and episode number, split-cour
halves and One Piece-style long-runners included. Two gaps matter once
the app WRITES to MAL rather than just reading skip times:

- **Kitsu-keyed titles** (some anime catalogs key titles `kitsu:ID`) miss
  today, because the index is keyed by IMDb only. The dataset carries
  `kitsu_id` too, one-to-one with MAL ids in 19,958 cases, so a second
  index covers them. That a Kitsu episode number equals MAL's for every
  entry is unconfirmed.
- **26 IMDb ids have two rows on the same season and offset** (a TV entry
  and an OVA, say). For skip times the first one does; for a write it
  could count your episode on the wrong entry. Writes take the TV row
  when one of them is TV, and skip the title otherwise (D5).

## Decisions

**D1. What goes to MAL.** When you finish an anime episode here (the same
moment the app ticks it: 90% through, or the end), its MAL entry's
episode count goes up to that episode, status "watching", or "completed"
when it was the last one. Never down: rewatching episode 3 of something
you're 10 into changes nothing. *Recommend exactly this.* Scores stay
yours to set on MAL.

**D2. What comes back.**
- (a) Nothing: MAL is where the app reports, not where it reads.
- (b) **Your MAL counts tick episodes here**: a series you're 12 into on
  MAL shows episodes 1 to 12 ticked in its grid, and the next episode
  follows, even if you watched them elsewhere.
- (c) (b), plus a "MAL Plan to Watch" list in Library, two-way, the way
  the Trakt Watchlist is.
*Recommend (b).* It is why anyone connects, and it is cheap once the
mapping exists. (c) is more work for a list most people keep on MAL's
own site; it can follow.

**D3. Trakt and MAL both connected.** Both can tick an anime episode.
*Recommend: a tick from either counts* (ticks only add). Trakt stays the
ledger for everything that is not anime.

**D4. How you sign in.** A browser opens MAL; the app listens on
`http://localhost:47391/` for the one redirect, and nothing else. It is
the standard desktop pattern and needs no new library (the stream proxy's
hyper server is already in the tree). The alternative, a
`blammytv://` link registered with Windows, is unconfirmed with MAL for
this app type and means an installer change. *Recommend the loopback.*

**D5. Titles the mapping can't place for certain** (no MAL entry, or a TV
and an OVA on the same season). *Recommend skipping them*, and taking the
TV entry when exactly one candidate is TV.

**D6. Kitsu-keyed titles.** *Recommend including them* through the
dataset's Kitsu ids, with the episode number as given. If a real title
turns out numbered differently, it gets a correction then.

## Build order

1. **B1, native:** `mal.rs`, the same shape as `trakt.rs`: the PKCE
   sign-in with a one-shot loopback listener, refresh behind the token
   lock, two Credential Manager entries, form-encoded requests paced one a
   second, a 403 HTML page read as "MAL is refusing this app" rather than
   a parse error. Tests against a fake MAL in the host crate.
2. **B2:** the mapping as a shared resolver: the IMDb index as today plus
   a Kitsu index and the TV-first rule, with tests on the 26 doubles.
3. **B3:** progress out (D1), from the moment the app ticks an episode.
4. **B4:** counts in (D2 b), when a series' page opens and at launch.
5. **B5:** the Settings row under Accounts, next to Trakt.
6. **Harness:** `verify-mal` with a fake MAL, the way verify-trakt works.

## Risks

- **The loopback port is taken** by something else on Adam's machine. The
  sign-in says so and names the port; a second registered port is the
  fix if it ever happens.
- **MAL has changed its auth before** (the S256 lesson). Read
  `expires_in`, never assume.
- **Unchecked from the build box:** the whole sign-in against the real MAL,
  whether list reads need `nsfw=true` to include everything, and the
  Kitsu episode numbering.
